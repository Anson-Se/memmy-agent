# 官方插件市场：一期前端与后续接入

## 统一规则

产品规则以 [插件安装与权限 PRD](./plugin-permission-model.md) 为准；本文补充一期界面和现有实现边界，不覆盖该 PRD。

插件各自声明可见、安装和使用规则，主程序依据服务器资格统一执行。三个插件均运行时按需下载，不将成品插件包打进 App 安装包。

| 插件 | 可见范围 | 首次安装策略 | 使用要求 |
| --- | --- | --- | --- |
| 法律 | 登录且获得法律白名单资格后可见 | 资格满足后自动安装 | 登录且白名单资格有效 |
| 文献综述 | 所有人；未登录提示去登录 | 登录后自动安装 | 登录用户；推荐官方模型 |
| Office | 所有人 | 用户安装 | 已安装 |

三类插件都允许卸载和重新安装。资格满足时自动安装须尊重主动卸载记录，不能在重启或资格刷新后自动装回。App 启动、打开插件面板、刷新和定期或服务器推送的资格变更均需重新判断；先登录后开白无需重新登录。插件默认自动更新，更新前重新校验资格。

资格失效时保留插件文件、停止更新并阻止新任务，进行中的任务允许完成。文献综述已安装但未登录时显示不可用状态；法律无白名单资格时隐藏。恢复资格后直接可用，无需重新下载。

官方模型仅在插件详情页推荐；对话中不强制、不额外弹提示，模型选择器保持可用，用户可自由选择自有模型。

本期目录均为 Memmy 官方插件。点击“安装”后连续完成下载、应用官方插件声明的权限和启用，不再弹出安装或权限确认。达到真实 active 状态后才表示安装完成。中途失败显示实际状态并允许重试；卸载保留确认。此规则只用于官方目录，不改变通用第三方插件的权限策略。

安装状态与使用要求分开：未安装、安装中、已安装、安装异常。没有官方模型也能查看或卸载文献综述插件。模型推荐在详情中说明，不占据插件列表的主要位置。

## 入口与连接的关系

侧边栏保持“连接与工具”，沿用 `/tools` 页面，不增加独立插件入口。

- 应用工具：第一个切换按钮，默认打开。让 Memmy 访问和操作 GitHub、Notion、Google Drive 等应用；使用连接、管理、断开操作。
- 聊天渠道：第二个切换按钮。从微信、Telegram、飞书等聊天应用向 Memmy 发任务、收结果；使用连接、配置、断开操作。
- 任务插件：第三个切换按钮。增加法律、文献综述、Office 等成套任务能力；使用安装、使用、卸载操作。

切换入口参考用户提供的 WorkBuddy 顶部导航形式：图标加文字，未选中项无边框。配色遵循 Memmy 现有主题：选中项复用导航浅绿色底，文字和图标使用深绿色，悬停为更浅的品牌色。不使用横贯页面的下划线页签。

页面顶部显示同一级的三个图标文字切换按钮，下面显示当前目录。三个分类依据用户目的，不依据安装包或连接协议；不再把渠道、应用工具塞进同一页而另开插件市场。三类共用内容宽度、标题说明、刷新、搜索、状态筛选和紧凑列表；工具的业务类别保留为应用工具内的次级下拉筛选。搜索和筛选在应用工具与聊天渠道之间各自保存。

插件列表使用每排三项的紧凑条目、小图标、名称和一句用途、右侧安装或管理操作。视觉沿用 Memmy 记忆页：复用 `memory-panel__header`、标题/说明、刷新按钮和筛选样式；条目使用相同的浅边框、圆角、文字层级和间距，不使用大面积卡片。内容宽度不超过900px时两列，不超过620px时单列；版本、模型推荐、能力说明放详情。演示条件收进可展开的“交互预览”区，避免预览控件抢占产品内容。

插件用“安装/卸载”，外部服务用“连接/断开”。安装 Office 不等于授权 Microsoft 365；卸载插件不会操作用户的外部账号连接。现有新手引导仍进入连接页。

品牌不是分类依据：同名 Discord 的应用工具和聊天渠道使用独立目录身份与原有 API；搜索或已连接状态不会把两者合并。法律资格、自动安装和模型推荐是条目政策，不决定一级分类。

应用工具和聊天渠道的条目只显示图标、名称及实际连接状态，不逐项重复“连接某账号”等通用说明。宽窗口每行四项，随内容宽度缩为三列、两列、单列。任务插件保留有区分度的用途说明，宽窗口每行三项。

插件详情采用“场景示意图＋简短介绍”：上方柔和主题色背景展示三条具体使用示例，下面一段用途说明，自动安装、模型推荐、账号要求收为简短说明。示例是静态介绍，不是执行按钮；安装和卸载仍由底部明确操作触发。弹窗限制在视窗高度内，正文可滚动，关闭和操作区始终可达。

## 当前分支落地范围

此节描述 `plugin-marketplace` 分支代码现状，不能作为已满足 PRD 的声明。详细核对见 [实现现状与差距](./plugin-marketplace-implementation-status.md)。

- 文献综述：桌面资源目录目前仍声明 `0.5.25` 捆绑包；市场读取 Host 真实安装状态，用户操作可串联安装、权限批准和启用，并持久记录主动卸载。资格驱动远程分发尚未完整替代捆绑启动流程。
- Office、法律：前端写死目录条目且都标记 `installable: true`；没有据服务器资格过滤法律，也没有据正式发布产物决定 Office 的“即将上线”状态。不能将 UI 占位条目认定为正式发布。
- 官方模型：详情已采用推荐文案，但前端仍残留“需配置模型”状态和动作。后端已有可选的 manifest 模型限制，需核对文献综述实际发布包，确保符合仅推荐规则。
- 开发交互预览：`?memmyRoute=/tools&plugin-market-preview=1`。仅开发环境动态加载，不调用真实插件、账号或权限 API；预览不代表资格控制已落地。

法律用途来自 `legal/e83d4238` 的劳动用工场景；Office 来自 `upstream/v1.1.5/c13b8887` 的 docx、xlsx、pptx、pdf 技能。它们的独立插件发布需后续接入。

## 后续接入边界

1. 将分发、自动或手动安装、可见性及使用规则声明到插件 manifest，兼容现有公开、手动安装插件；替换主程序中的具体插件政策。
2. 官方目录接口按当前账号资格过滤，并返回安装资格、使用资格、阻塞原因、版本、发布状态和真实安装状态。前端不接收白名单用户清单。
3. 安装、启用、工具发现、恢复和新任务执行由 Host 校验服务器资格；服务器按资格发包，插件功能调用服务端二次校验。账号切换后重新判定。
4. 自动安装和更新统一依据资格刷新，尊重主动卸载记录；Office 保持手动安装。资格失效保留文件并允许已有任务完成，恢复后无需重新下载。
5. 法律、Office 的正式发布包与校验值接入目录；文献综述改为运行时按需下载，三个成品插件包均不捆绑到 App。
6. 官方模型只作为详情页推荐，不锁定模型选择器、不阻止自有模型使用、不增加对话提示。插件内部推理和 Agent 会话均需核对实际路由与推荐规则一致。
